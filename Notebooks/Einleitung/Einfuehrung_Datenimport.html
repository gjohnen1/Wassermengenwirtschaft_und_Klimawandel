Jupyter Notebooks, Python und KI-unterstütztes Programmieren#

Einführungsnotebook zum Kurs „Wassermengenwirtschaft und Klimawandel”

Willkommen zum ersten Notebook. Dieses Notebook ist auf einen Tagesblock (2 × 1,5 h) angelegt und legt die Grundlage für alle folgenden Übungen.

Lernziele#

Nach Bearbeitung dieses Notebooks könnt Ihr:

  1. Jupyter-Zellen ausführen, die Umgebung aufsetzen (lokal / Binder / Colab) und die drei zentralen Bibliotheken pandas, numpy, matplotlib einsetzen.

  2. Die wichtigsten Python-Bausteine lesen und anpassen: Variablen, Datentypen, Funktionen, if-Anweisungen, for-Schleifen, Listen und Dictionaries.

  3. Eine reale hydrologische CSV-Datei einlesen, Datentyp- und Lückenprobleme diagnostizieren und mit pandas bereinigen.

  4. KI-Assistenten (GitHub Copilot und Chat-LLMs wie Claude / ChatGPT) gezielt und kritisch einsetzen — Prompts formulieren, generierten Code verstehen, validieren und notfalls verwerfen.

Das Kursziel ist Hydrologie, nicht Programmierung. Python und KI sind Werkzeuge, die Ihr nicht beherrschen müsst wie ein Software-Engineer — aber Ihr müsst sie lesen, prüfen und verantworten können. Der rote Faden dieses Notebooks ist deshalb: Grundlagen reichen, um KI-Output kritisch zu bewerten.

Zellen ausführen — die Mechanik#

Eine Jupyter-Zelle führt Ihr aus mit:

  • Shift + Enter — Zelle ausführen und zur nächsten springen (empfohlener Default)

  • Ctrl + Enter — Zelle ausführen, Cursor bleibt in der Zelle

  • Klick auf den Run-Pfeil in der Symbolleiste

Wichtig: Zellen werden in der Ausführungsreihenfolge interpretiert, nicht in der Darstellungsreihenfolge. Die Zahl links neben einer Codezelle ([3]:) zeigt, als wievielte Zelle sie ausgeführt wurde. Wenn Ihr eine Zelle oben ändert und weiter unten erneut ausführt, kann der Kernel Zustände mischen — im Zweifel hilft Kernel → Neu starten und alle Zellen ausführen.

Ihr werdet in diesem Kurs mit GitHub Copilot (über den kostenlosen GitHub Student Developer Pack — aktiviert Euren Account vor dem nächsten Termin) und ergänzend mit einem Chat-LLM (Claude, ChatGPT, Gemini) arbeiten. Block B — Python-Basics auf der Kurzstrecke#

Dieser Block ist bewusst knapp gehalten. Die Beispiele sind, wo möglich, hydrologisch motiviert. Wenn Euch etwas fremd vorkommt: nicht weiterlesen, sondern die Zelle direkt darüber modifizieren, nochmal ausführen, Ergebnis anschauen. Das ist der schnellste Lernweg in einem Notebook.

1. Variablen und Datentypen#

Eine Variable ist ein Name für einen Wert. Die vier wichtigsten einfachen Datentypen:

Typ

Zweck

Beispiel

int

ganze Zahl

anzahl_pegel = 7

float

Dezimalzahl

mittlerer_abfluss_m3s = 12.4

str

Text (in Anführungszeichen)

pegelname = "Rinderbach"

bool

Wahrheitswert

Mit type(...) fragt man den Typ einer Variable ab. Einheiten gehören bei uns konventionell in den Variablennamen (..._m3s, ..._m) — das ist kein Python-Zwang, aber guter Stil und erspart später Einheitenfehler.

# Vier Variablen mit den vier Grundtypen
anzahl_pegel = 7                          # int
mittlerer_abfluss_m3s = 12.4              # float
pegelname = "Rinderbach"                # str
ist_hochwasser = False                    # bool

for name, wert in [("anzahl_pegel", anzahl_pegel),
                   ("mittlerer_abfluss_m3s", mittlerer_abfluss_m3s),
                   ("pegelname", pegelname),
                   ("ist_hochwasser", ist_hochwasser)]:
    print(f"{name:25s} = {wert!r:15s}  → {type(wert).__name__}")

anzahl_pegel              = 7                → int
mittlerer_abfluss_m3s     = 12.4             → float
pegelname                 = 'Rinderbach'     → str
ist_hochwasser            = False            → bool

2. Type-Casting — Typen umwandeln#

Manchmal kommt ein Wert in der „falschen” Form an. Klassisches Beispiel: eine Zahl ist als Text (str) gespeichert und lässt sich nicht rechnen. Dann castet man:

  • int(x) — nach Ganzzahl (schneidet Nachkommastellen ab, rundet nicht!)

  • float(x) — nach Dezimalzahl

  • str(x) — nach Text

# Beispiel: Wasserstand als String aus einer CSV — in float umwandeln
wasserstand_str = "1.47"
wasserstand_float = float(wasserstand_str)
print(f"{wasserstand_str!r:10s} (Typ {type(wasserstand_str).__name__}) "
      f"→ {wasserstand_float} (Typ {type(wasserstand_float).__name__})")

# int() schneidet ab, rundet nicht:
print(f"int(1.7) = {int(1.7)}     <-- NICHT 2!")

'1.47'     (Typ str) → 1.47 (Typ float)
int(1.7) = 1     <-- NICHT 2!

3. Funktionen#

Eine Funktion kapselt wiederverwendbaren Code. Syntax: def name(parameter): .... Mit return gibt die Funktion ein Ergebnis zurück.

Faustregel: sobald Ihr denselben Code zum dritten Mal schreibt, ist eine Funktion überfällig.

def abfluss_aus_wasserstand(stage_m, a=2.5, b=1.6):
    '''
    Potenzgesetz-Pegelschlüssel: Q = a * (stage)^b

    Parameter:
        stage_m (float): Wasserstand in Metern.
        a, b (float):    Kalibrierungsparameter (Default: Beispielwerte).

    Rückgabe:
        float: Abfluss in m³/s.
    '''
    return a * stage_m ** b

# Aufruf
q = abfluss_aus_wasserstand(1.4)
print(f"Bei stage = 1.4 m → Q ≈ {q:.2f} m³/s")

# Mit benannten Argumenten — genauso gültig, aber lesbarer:
q2 = abfluss_aus_wasserstand(stage_m=1.4, a=3.0, b=1.5)
print(f"Mit anderen Parametern → Q ≈ {q2:.2f} m³/s")

Bei stage = 1.4 m → Q ≈ 4.28 m³/s
Mit anderen Parametern → Q ≈ 4.97 m³/s

4. Kontrollfluss — if / else#

Mit if führt Ihr Code nur dann aus, wenn eine Bedingung wahr ist. Achtet auf den Doppelpunkt und die Einrückung (vier Leerzeichen). Python erzwingt die Einrückung syntaktisch.

abfluss_m3s = 185.0
warnschwelle_m3s = 150.0

if abfluss_m3s > warnschwelle_m3s:
    print(f"WARNUNG: Abfluss {abfluss_m3s:.0f} m³/s "
          f"über Schwelle ({warnschwelle_m3s:.0f} m³/s).")
else:
    print(f"OK: Abfluss {abfluss_m3s:.0f} m³/s unter Schwelle.")

WARNUNG: Abfluss 185 m³/s über Schwelle (150 m³/s).

5. Listen, for-Schleifen und Dictionaries#

Für die späteren Übungen braucht Ihr drei Strukturen:

  • Liste ([...]) — geordnete Sammlung, indiziert ab 0.

  • for-Schleife — „mache etwas für jedes Element in einer Liste”.

  • Dictionary ({...}) — Zuordnung Schlüssel → Wert, z.B. Pegelname → Einzugsgebietsgröße.

# Eine Liste aus Tages-Wasserständen [m]
wasserstaende_m = [1.12, 1.18, 1.23, 1.31, 1.47, 1.55, 1.48]

print(f"Anzahl Messungen: {len(wasserstaende_m)}")
print(f"Erster Wert:      {wasserstaende_m[0]}")
print(f"Letzter Wert:     {wasserstaende_m[-1]}")

# for-Schleife: Abfluss aus jedem Wasserstand schätzen
print("\nBerechnete Abflüsse:")
for i, stage in enumerate(wasserstaende_m):
    q = abfluss_aus_wasserstand(stage)      # Funktion von oben wiederverwendet
    print(f"  Tag {i+1}: stage = {stage:.2f} m  →  Q ≈ {q:.2f} m³/s")

Erster Wert:      1.12
Letzter Wert:     1.48

  Tag 2: stage = 1.18 m  →  Q ≈ 3.26 m³/s
  Tag 3: stage = 1.23 m  →  Q ≈ 3.48 m³/s
  Tag 4: stage = 1.31 m  →  Q ≈ 3.85 m³/s
  Tag 5: stage = 1.47 m  →  Q ≈ 4.63 m³/s
  Tag 6: stage = 1.55 m  →  Q ≈ 5.04 m³/s
  Tag 7: stage = 1.48 m  →  Q ≈ 4.68 m³/s

# Dictionary: Pegel → Einzugsgebietsgröße [km²]
pegel = {
    "Rinderbach":     14.4,
    "Ruhr":         4485.0,
    "Rhein":      185000.0,
}

# Zugriff per Schlüssel
print(f"Einzugsgebiet Rinderbach: {pegel['Rinderbach']} km²")

# Über alle Einträge iterieren
print("\nAlle Pegel:")
for name, flaeche_km2 in pegel.items():
    print(f"  {name:15s} → {flaeche_km2:>10.1f} km²")

Block C — Von der CSV zur sauberen Zeitreihe#

Dieser Block ist das Herzstück des Notebooks. Wir gehen den vollständigen Arbeitsablauf einmal durch: Datei finden → einlesen → Qualitätsprobleme diagnostizieren → beheben → visualisieren.

In diesem Kurs arbeiten wir mit Wasserstands- und Durchflussdaten von Wasserwirtschaftsverbänden (z. B. Bergisch-Rheinischer Wasserverband, Ruhrverband) und Wetterdiensten (z. B. Dateipfade verstehen#

Ein grundlegendes, aber enorm wichtiges Konzept: Wie liest man eine Datei ein, die irgendwo im Dateisystem liegt?

In Windows/macOS klickt Ihr eine Datei an und das passende Programm öffnet sie. In Python geht es umgekehrt: Ihr müsst explizit angeben, wo die Datei liegt. Jupyter-Notebooks interpretieren Dateipfade relativ zum Speicherort der Notebook-Datei, sofern kein absoluter Pfad angegeben wird.

Unsere Notebook-Datei liegt unter

Die Daten, die wir einlesen wollen, liegen unter

Absoluter vs. relativer Pfad#

Es gibt zwei Wege, einer Datei den Weg zu weisen:

1. Absoluter Pfad — vom Wurzelverzeichnis des Dateisystems aus, z.B. C:\Users\IhrName\Projekt\Inhalt\Projekt_Daten\Pegel_Beispiel_stage_data.csv (Windows) oder /home/ihrname/Projekt/Inhalt/Projekt_Daten/Pegel_Beispiel_stage_data.csv (Linux/macOS). Nachteil: funktioniert nur auf genau diesem Computer — verschiebt Ihr das Projekt oder teilt es mit einer Kommilitonin, bricht es.

2. Relativer Pfad — relativ zum Ort der Notebook-Datei. Portabel, also bevorzugt.

  • . — aktuelles Verzeichnis.

  • .. — ein Verzeichnis nach oben.

Wir sind in Inhalt/Notebooks/Einleitung/, die Daten in Inhalt/Projekt_Daten/. Also: zweimal nach oben (../../) und dann in Projekt_Daten/.

Pfade sauber bauen — und das DRY-Prinzip#

Gemäß dem Prinzip Don’t Repeat Yourself speichert man Pfade in Variablen — einmal oben im Notebook, danach nur noch über den Variablennamen referenziert. Mehrmaliges Tippen = höhere Fehleranfälligkeit.

Variablennamen sollten aussagekräftig sein und Einheiten nicht verschleiern. Wenn Ihr einen mittleren Jahresabfluss speichert, ist qa heute verständlich, aber in einem Jahr niemandem mehr klar — avg_annual_flow_m3s enthält den Zweck und die Einheit (m³/s ↔ „cubic metres per second”). Einheiten sind wichtig.

# ----- Variante A: klassisch mit os.path.join (sehr verbreitet in älterem Code) -----
data_folder_relative = '../../Projekt_Daten/'
file_name = 'Pegel_Beispiel_stage_data.csv'
demo_data_path = os.path.join(data_folder_relative, file_name)

print("Variante A (os.path.join):")
print(f"  {demo_data_path}")

# ----- Variante B: modern mit pathlib (Python 3.4+) -----
data_folder = Path('../../Projekt_Daten')
demo_data_path_pl = data_folder / file_name   # der '/'-Operator baut den Pfad

print("\nVariante B (pathlib):")
print(f"  {demo_data_path_pl}")
print(f"  existiert? → {demo_data_path_pl.exists()}")

Variante A (os.path.join):
  ../../Projekt_Daten/Pegel_Beispiel_stage_data.csv

Variante B (pathlib):
  ..\..\Projekt_Daten\Pegel_Beispiel_stage_data.csv
  existiert? → True

Hinweis zu pathlib: Für neue Projekte ist pathlib.Path der empfohlene Weg — er löst das Windows/Unix-Backslash-Problem automatisch und lässt sich eleganter lesen. In älteren Code-Basen (und in vielen LLM-Antworten) trefft Ihr aber weiterhin auf os.path.join — beide sind korrekt. In diesem Notebook nutzen wir im Weiteren die os.path.join-Variante, damit Ihr beide Schreibweisen gesehen habt.

  2. Er nennt die Bibliothek (matplotlib), nicht „irgendein Plot”.

  3. Er nennt konkrete Anforderungen (Achsenbeschriftung, Lücken, Figsize).

4. Der Verifikationsworkflow — warum das alles zählt#

Jeder Vorschlag, egal ob Inline oder Chat, durchläuft bei Euch vier Schritte:

  1. Lesen — versteht Ihr, was der Code tut? Bei jedem Aufruf: welche Funktion, welche Bibliothek, welcher Rückgabewert?

  2. Ausführen — im Notebook in einer eigenen Zelle. Nie direkt in produktivem Code-Abschnitt einfügen.

  3. Prüfen — hier wird es hydrologisch:

    • df.shape vor- und nachher: passt die Zeilenzahl?

    • df.describe(): sind Minimum/Maximum/Mittelwert plausibel?

    • Einheiten: rechnet der Code in m oder cm, in m³/s oder cfs?

    • Plot: sehen die Werte so aus, wie sie sollten?

  4. Übernehmen oder verwerfen — erst danach in die Hauptzellen Eures Notebooks.

Beispiel: ein LLM schlägt vor, df.dropna() statt df.interpolate() zu verwenden. Beides ist Code, der läuft. Der Unterschied:

5. Fehlermeldungen als Dialog#

Stacktraces sind in Wahrheit der Anwendungsfall, in dem LLMs glänzen. Workflow:

  1. Komplette Fehlermeldung kopieren (von Traceback (most recent call last): bis zur letzten Zeile).

  2. In den Chat-LLM einfügen, mit einem Satz Kontext: was wolltet Ihr tun, welcher Code hat den Fehler erzeugt.

  3. Antwort lesen, Lösung prüfen (siehe Verifikationsworkflow oben).

Beispiel-Prompt-Vorlage:

„Ich bekomme in einem Jupyter-Notebook folgenden Fehler, wenn ich df['Value'].astype(float) aufrufe:

ValueError: could not convert string to float: '1.47 '

df ist ein Pandas DataFrame mit Pegel-Wasserstandsdaten (BRW). Was ist die Ursache, und welche drei Alternativen zum Beheben gibt es (mit ihren jeweiligen Trade-offs)?”

Das funktioniert weit besser als „warum geht mein Code nicht”.

6. Halluzinationen — wenn KI eine Funktion erfindet#

LLMs erfinden gelegentlich Python-Funktionen, die es gar nicht gibt. Ein reales Beispiel, das Studierenden immer wieder passiert:

„Nutze df.interpolate_nans(method='cubic') für die Lückenfüllung.”

Diese Funktion existiert nicht in pandas. Richtig wäre df.interpolate(method='cubic'). Woran Ihr eine Halluzination erkennt:

  • Die Methode ist in der offiziellen pandas-Dokumentation nicht zu finden.

  • Im Notebook wird beim Ausführen ein AttributeError: 'DataFrame' object has no attribute '...' geworfen.

  • Der Parameter (method=...) wird in einer Variante vorgeschlagen, die die Originalfunktion gar nicht unterstützt.

Gegenmittel: Bei jedem neuen Funktionsnamen, den Euch ein LLM vorschlägt, einmal kurz die Doku oder StackOverflow öffnen. Das dauert 20 Sekunden und spart Euch später Stunden Fehlersuche.

7. Datenschutz und Vertraulichkeit#

  • Keine personenbezogenen Daten in Prompts (weder Eure noch die von Anderen).

  • Projektdaten unter NDA / vertrauliche Pegeldaten dürfen nicht in ein Chat-LLM eingegeben werden. Copilot (mit Business-/Enterprise-Lizenz) ist hier strenger; die kostenlose Studenten-Version und Chat-LLMs sind das nicht — behandelt sie wie ein öffentliches Forum.

  • Bei Unsicherheit: abstrahiert (ersetzt Pegelnamen, Orte, konkrete Projektbezüge durch Platzhalter). Ein LLM kann Euch bei einem Datenqualitätsproblem genauso gut helfen, wenn die Spalte im Prompt stage_m statt Pegel_KlientXY_vertraulich heißt.

  • Für die Hausarbeit in diesem Kurs dürft Ihr KI frei nutzen — dokumentiert aber in einem kurzen Satz, wo und wie.

Block E — Meta-Reflexion, Checkliste, Ausblick#

Zusammenfassung#

In diesem Notebook habt Ihr fünf Dinge gelernt:

  1. Jupyter bedienen — Zellen ausführen, Kernel verstehen, Umgebung einrichten.

  2. Python lesen — Variablen, Typen, Funktionen, if, Listen, for-Schleifen, Dictionaries.

  3. Dateipfade beherrschen — absolute vs. relative Pfade, os.path.join und pathlib.

  4. Einen kompletten Datenworkflow durchgespielt — von der CSV über Qualitätschecks bis zur interpolierten Zeitreihe und ihrem Plot.

  5. KI-Assistenten souverän einsetzen — Inline (Copilot) und per Chat, mit klarem Verifikationsworkflow.

Der wichtigste Take-away: Ihr seid der Filter zwischen Daten und Entscheidung. KI beschleunigt Eure Arbeit, aber ersetzt nicht Eure Urteilsfähigkeit über Plausibilität, Einheiten und Datenqualität.
